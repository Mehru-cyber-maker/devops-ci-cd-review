# Input formats

Select the release digest independently of the records being checked. A SHA-256 is 64 hexadecimal characters without `sha256:`. Hexadecimal case is normalized.

`--artifact` hashes the exact bytes of a local file. `--sha256` accepts an externally selected digest. The tool cannot infer whether that digest is a file, OCI manifest, or another artifact identity.

## Policy

```json
{
  "schema_version": 1,
  "allowed_builders": ["https://example.org/builders/student-demo/v1"],
  "expected_source": {
    "uri": "git+https://example.org/student/demo.git",
    "commit": "1111111111111111111111111111111111111111"
  },
  "max_scan_age_hours": 72,
  "blocked_severities": ["HIGH", "CRITICAL"]
}
```

All five fields are required; unknown policy fields are rejected to catch spelling mistakes. Builder and source URI comparisons are exact. Source commits must contain the full 40- or 64-character digest. Scan age must be an integer from 1 to 8760 hours.

Supported severities are `UNKNOWN`, `LOW`, `MEDIUM`, `HIGH`, and `CRITICAL`. The policy can block any nonempty subset. An unrecognized severity makes the scan invalid. The sample policy permits `UNKNOWN`; add it to the blocking list if your release policy requires that.

## Provenance

Required structure:

- `_type`: `https://in-toto.io/Statement/v1`.
- `predicateType`: `https://slsa.dev/provenance/v1`.
- `subject`: nonempty list of named subjects with valid `digest.sha256` fields; at least one must match the selected release.
- `predicate.buildDefinition.buildType`: nonempty string.
- `predicate.buildDefinition.resolvedDependencies`: array of objects containing `uri` and `digest`.
- `predicate.runDetails.builder.id`: declared builder identifier.

At least one resolved dependency must match the expected source URI and `digest.gitCommit`. Conflicting commits for that URI fail the check. Other dependencies and additional subjects are allowed.

This is a supported structural subset, not full SLSA or in-toto schema validation. DSSE envelopes are rejected. If using signed attestations, verify them with an external verifier first and preserve the authenticated statement through trusted collection. Merely decoding a payload does not authenticate it.

## SBOM

Required fields:

- `bomFormat`: `CycloneDX`; `specVersion`: `1.5` or `1.6`.
- `version`: positive integer.
- `metadata.component.name` and `metadata.component.hashes`.
- A root-component hash with `alg: "SHA-256"` and `content` equal to the selected artifact digest.

Different SHA-256 values for the root component cause failure. Hashes of nested dependencies cannot substitute for the root artifact identity. A `components` array is optional; if supplied, entries need a component name.

Some SBOM generators omit the root artifact digest or use a different identity. Preserve their original output. A trusted collector must establish the correct binding before adapting the data; copying an unrelated digest into the SBOM is not evidence of correctness.

## Normalized vulnerability scan

```json
{
  "schema": "evidencegate.scan/v1",
  "subject": {"sha256": "replace-with-64-hexadecimal-characters"},
  "scanner": {"name": "Trivy", "version": "record-the-actual-version"},
  "scanned_at": "2026-10-25T09:00:00Z",
  "status": "complete",
  "vulnerabilities": [
    {"id": "SYNTHETIC-001", "package": "example-package", "severity": "HIGH"}
  ]
}
```

The example digest above is a placeholder, not a valid digest. Use an actual 64-character value. The examples generated by `demo` contain valid synthetic values.

All shown fields are required. Each vulnerability needs a nonempty ID and package plus a supported severity. An empty vulnerability array is allowed; an absent array or a partial status is not treated as a clean scan.

Dates need a timezone. The maximum age is inclusive; future dates are allowed only within five minutes of the assessment time. `check --at` records an explicit historical assessment time for reproducible audits; normal checks use the current UTC time.

The scan record is a normalization contract, not a signed attestation. Its timestamp, subject, scanner identity, and complete status are claims supplied by the collection process.

## Input handling

JSON inputs are limited to 8 MiB. The dashboard limits the complete request to 8 MiB; uploaded files are retained only in browser/server memory. Duplicate object keys and nonstandard `NaN`/`Infinity` constants are rejected.

Unsupported or missing evidence cannot produce a passing assessment. A malformed JSON file or invalid policy returns an input error rather than a release report.
